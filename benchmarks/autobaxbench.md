## What It Tests
Whether a model writes **backends that are both correct and secure**.

- **Scale** — 560 tasks from 40 scenarios across 14 frameworks.
- **Three tiers** — easy, medium and hard.
- **Specification-driven** — each task gives an OpenAPI spec and asks for a full implementation.

## How It Scores
**Functional tests plus black-box exploits.**

- **Functional** — fixed tests on the REST endpoints.
- **Functional plus secure** — only counted if every functional test passes first.
- **Exploits** — target specific weaknesses.

## Format
A single generation per task from an OpenAPI description. Tests and exploits talk to the implementation over REST, so they do not depend on the language or framework.

## Limitations
- **Generated tasks.** Quality depends on AutoBaxBuilder, validated against expert tests.
- **Specific exploits.** A pass means resistance to those exploits only.
- **Vendor note.** Google's table says results were provided by the benchmark's authors.

## Example
BaxBench, which this benchmark extends, gives each scenario a natural-language description and **REST endpoints formally specified in OpenAPI**, with examples of inputs and outputs. The model writes the backend; the benchmark then runs functional tests and exploits through the endpoints. A backend that works but accepts an injection fails the secure measure.
